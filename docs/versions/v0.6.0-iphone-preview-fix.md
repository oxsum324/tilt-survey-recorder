# V0.6.0 手機成果預覽修正

日期：2026-11-05。本機分支 `codex/fix-iphone-report-preview`；本文件不代表正式網站已更新。

## 已確認的問題

在 375×667 手機尺寸，已確認讀數的合成案件可產生三頁報告，但按「更新預覽」後，第一頁仍位於視窗下方，頂端約 672 px，畫面停在輸出選項。原介面沒有預覽進度、完成頁數或直接查看報告的入口。

產生報告時若發生非資料檢查類的例外，舊流程會清空報告，把原因送到通用訊息列；手機訊息列位於收合的「狀態」選單內，成果頁看起來只有空白，且預覽就緒旗標一直停在未完成。

使用者回報 iPhone／Safari 無法看到預覽。本次重現的是上述介面問題，尚未取得使用者 iPhone 的畫面或案件資料，不能把模擬結果當成該手機的最終根因或實機驗收。

## 修正

- 成果頁新增預覽進度、完成頁數與「查看報告預覽」連結。
- 手機按「更新預覽」後，成功時定位到報告；有未完成事項或失敗時定位到成果頁的原因。
- 原有讀數確認、附件資料檢查仍會阻擋未完成成果；錯誤結束後可重新產生預覽，列印與下載仍要求有效成果。
- 預覽不改寫案件、讀數、更正原因、確認快照或原始媒體。
- 更新 service worker 的內容指紋快取名稱，供日後發布時觸發資源更新；本次未清除網站資料。
- `test:browser` 納入 `tests/report-preview-browser.mjs`；CI 安裝增加固定 Playwright 版本的 WebKit，原 Chrome／Edge 檢查保留。

- `npm.cmd run test:report-preview`：Chrome／WebKit 各 375×667、390×844、1280×900，包含定位、狀態、失敗顯示、失敗恢復、案件不變；390 px 另檢查五頁完整附件、獨立照片／佈設圖／成果表與列印狀態，共 28 項。

失敗紀錄均保留：

- `output/preview-iphone-red-20261105.log`：修正前，375 px 按更新後第一頁仍在視窗外，斷言失敗。
- `output/preview-iphone-attachments-20261105.log`：補測使用了底圖影像範圍外的點位，未放置測點；改為點選底圖影像本身，保留五頁附件斷言。
- `output/preview-iphone-attachments-v2-20261105.log`：Windows WebKit 的暫時儲存區無法保存 Blob；另以中文與英文路徑的持久儲存區逐一診斷，英文暫存路徑可保存原檔。
- `output/preview-iphone-attachments-v3-20261105.log`：WebKit 測試改用英文路徑的獨立持久儲存區後，28 項均通過，既有斷言未放寬。產品 `store.js` 未更動。

截圖與每次結果 JSON 位於 `output/playwright/report-preview/`；失敗前的畫面、環境診斷 JSON 與舊收據仍保留。

## 限制

WebKit 在 Windows 執行，並非 iPhone 實機；本機 Windows 顯示縮放也會影響其截圖與 viewport 尺寸對照。尚待使用者以原 iPhone／Safari、原案件確認預覽、附件、列印及下載。未宣稱相機、剪貼簿權限或戶外常亮已驗收。未推送、未合併、未發布。

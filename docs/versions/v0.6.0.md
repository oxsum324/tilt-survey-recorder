# 傾斜測量紀錄 V0.6.0｜底圖立面朝向與立面示意模式

日期：2026-11-04。承接已發布的 V0.5.1 main `7048b27`，由 `feature/v0.6.0-plan-facing-schematic-elevation` 分支以 PR 交付。

## 背景

使用者提出兩個現場問題：平面圖上的測點只有點位與編號，讀圖者無法判定「向左傾」是底圖上哪個方向；立面示意圖必須逐層填準確樓高，現場常只知道大約幾層樓。

## 平面圖：立面朝向與傾斜方向

- 立面新增 `planNormalDeg`（null 或 0～360 之間的數），表示該立面的外法線在底圖上的方向，0＝底圖上方、順時針。同一立面的各測點組共用。
- 「平面圖標示」分頁新增朝向工具列：8 向按鈕、逆時針／順時針 15°、反向（180°）、依立面朝向（底圖北朝上時套用立面參數的外法線朝向，未填時停用）、清除。切換測點組時同步顯示該立面的設定。
- 設定後，每個已標位置的測點旁畫「⊥」視向符號：短線代表立面，箭頭由外側指向立面；觀測者站在箭頭尾端面向立面，圖上標「左」「右」字樣。
- 讀數已確認且偏移非零的分量，以箭頭畫出傾斜方向：立面內實線、立面外長虛線。未確認、零偏移或讀數不完整不畫。佈設圖輸出頁尾加入圖例。
- 未設定朝向時，佈設圖與 V0.5.1 完全相同。朝向只影響圖面，不進入 `observationSnapshot`，因此不改變方向判定、讀數與確認狀態。
- 不做底圖鏡像或翻轉：鑑定圖說的底圖必須與現場一致。

## 立面：快速樓層與示意模式

- 「立面參數」新增「樓層數＋標準層高」一鍵填入：1F 保留目前值，2F 以上以標準層高填入，仍可逐層修改。樓層數限 1～60，層高限 1～10000 cm，無效時提示且不改資料。
- 新增 `building.sketchMode`：`scaled`（既有行為，依樓高比例）或 `schematic`（樓層等高、不依比例）。示意模式只使用層數，樓高字串不參與繪圖與驗證，也不做高樓層省略；成果表示意圖固定註記「示意模式：樓層等高繪製，不依比例」。垂距 H 與 TB 離地高度仍標註實際數值。
- 測點組新增 `sketchMarks`（null 或 `{tb,tp}`，0～1 相對高度，tp 須大於 tb）。示意模式下「測點與讀數」每組多一張「立面示意位置」小圖：先點 TB 高度，完成後自動切為 TP，也可拖曳紅圈調整；清除後回到預設位置（TB 約 17%、TP 約 67%）。
- 示意位置只改圖面，不改讀數、H 與確認快照。

## 相容與資料

- 案件 schema 維持 1。`normalizeProject` 對三個新欄位只驗證範圍、不補寫（舊案件往返內容不變，缺漏一律視為未設定；新建案件才含預設值）：朝向須為 null 或 0≤x<360 的數、繪製方式限兩個值、示意位置須 0≤tb<tp≤1。
- 舊案件開啟時不寫回；使用者編輯後才保存含新欄位的內容。指紋排除欄位不變。
- 新增模組 `sketch-editor.js`（立面點選編輯器），已登錄 `build-site.mjs` 與 `sw.js` 快取清單；快取名稱末段依發布測試的 `cacheRevision` 重新計算。

## 驗證

- 單元測試新增 `plan.test.js`（向量、視向符號、傾斜箭頭、朝向不影響確認）、`sketch.test.js` 示意模式與編輯器模式、`store.test.js` 舊案件不補寫新欄位、新建含預設與無效值拒絕。
- 瀏覽器測試新增 `tests/elevation-plan-browser.mjs`：依樓層數填入、示意模式、示意位置點選與保存、成果表註記、底圖朝向 8 向／反向／15°／清除、佈設圖輸出圖例，全程無執行錯誤；並輸出 `output/elevation-plan/` 截圖。
- 既有 15 算例、`calc.js`、`report.js`、`pdf.js`、`integrity.js` 未改；A4 版面、CSP、Playwright 1.58.2 不變。

## 未納入本版

- 以現場照片為底點選 TB／TP 的「照片立面」：照片透視會讓尺寸示意失真，且成果表每格只有 93×87 的小圖，留待另案評估。
- 底圖北方向標示（非北朝上的 CAD 底圖）：目前以手動選向處理，「依立面朝向」只在北朝上底圖使用。
